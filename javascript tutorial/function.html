Concept

Function Kya Hota Hai? 🤔

Socho: ghar pe roz chai banti hai. Har baar kya karte ho? Paani ubalo → patti daalo → doodh daalo → cheeni... steps roz yaad karke repeat? 😩 Nahi! Ek baar seekh liya "chai banane ka tareeka" — phir bas bol do "chai bana do" aur ho gaya. Function bilkul yahi hai: code ka naam-rakha hua dabba — ek baar likho, jitni baar chaho bulao!

Juicer Machine Analogy

Juicer ek machine hai: seb daalo (INPUT) → machine andar kaam karta hai → juice nikalta hai (OUTPUT). Kal aam daaloge toh aam ka juice — machine SAME hai, input alag, output alag!

Programming mein: function makeJuice(fruit) { return fruit + " ka juice"; } — makeJuice("seb") do toh seb ka juice, makeJuice("aam") do toh aam ka juice. Pichle chapter ka loop (Ch4) yaad hai? Loop same kaam baar-baar chalata hai; function same kaam ko naam de ke reuse karne deta hai. Dono milkar bante hai DRY principle — Don't Repeat Yourself! 🔥

JavaScript mein functions ke 6 tools/styles hai — har ek ka apna moment. Sab cards dekho, phir ek-ek karke detail mein 👇

1. Function Declaration

function naam() { ... }

Standard tareeka — function keyword + naam + brackets + braces. Machine likhne ka basic format!

2. Parameters & Arguments

greet(name) → greet("Rahul")

Machine ke input holes — juicer mein fal daalo, us fal ka juice milega. Har call pe naya input!

3. return

return sum;

Machine se OUTPUT wapas — juice banake haath mein do! Return hote hi function khatam bhi ho jata hai.

4. Arrow Functions

const add = (a, b) => a + b

ES6 ka modern shortcut — one-line ka kaam ek line mein likho. Callbacks ka best friend!

5. Expression & Hoisting

let f = function() { ... }

Function value hai — variable mein store karo! Hoisting ka magic: declaration upar ud ke chalti hai!

6. Callbacks & IIFE

setTimeout(fn, 1000)

Function ko doosre function ko do (callback) ya turant chalao (IIFE) — apps ka asli raaz!

Tool #1

Function Declaration — Machine Banao 📦

Function banane ke liye 4 cheezein chahiye: function keyword + naam + brackets () + curly braces {}. Brackets mein input jaata hai, braces mein kaam hota hai. Aur sabse important — machine bana ke chhod nahi dete, use CALL karna padta hai!

// Syntax: function NAAM(parameters) { kaam } function wish() { console.log("Good morning! ☀️"); } // Machine ban gayi — par CHALI nahi abhi tak! // Chalane ke liye NAAM + () likho = CALL wish(); // ✅ call — "Good morning! ☀️" print hua wish(); // jitni baar chaho! wish(); // Naam ke baad brackets LAGANA zaroori hai: wish; // ❌ kuch nahi hoga — sirf naam ka zikr, call nahi!
BOMB ALERT: () Bhool Gaye Toh Kuch Nahi Hoga!

wish; aur wish(); mein zameen-aasmaan ka farak hai! Bina brackets = tumne function ka naam liya (dost ka naam liya par bulaya nahi 😄), brackets ke saath = call — machine chal padi! Sabse khatarnak baat: is mistake mein error bhi nahi aata — bas silent failure. Code "chal raha" dikhega par machine ne kaam kiya hi nahi. Debug karte waqt sabse pehle check: call mein () hai ya nahi?

Function Ke 3 Golden Rules

1. Naam verb (kaam) se shuru karo — greet, calcPrice, sendMsg, checkAge — naam padhte hi pata chal jaye machine kya karti hai!
2. Ek machine = ek kaam. Chai bhi banaye aur khana bhi — aisi machine mat banao. Chhoti machines ko jodkar bada kaam karo!
3. Define karna aadha kaam hai — call bhi karo! Bina call ke function sirf suitcase hai — band pada hai, safar nahi hua! 🧳

Tool #2

Parameters & Arguments — Machine Mein Daalo 🧃

Juicer mein fal daalte ho na? Wo holes hai parameters. Tum jo asli seb/aam daalte ho, wo hai arguments. Parameter = recipe ki khaali jagah (fruit), argument = asli value ("seb"). Machine ek, inputs hazaar — har baar naya output!

Tool #3

return — Machine Se Output Lo 📤

Machine ne kaam kar liya — ab result wapas do! Juicer ne juice banaya par haath mein nahi diya toh fayda kya? return function ka delivery boy hai — andar ka result bahar bhejta hai, jahan tum use variable mein store karo ya seedha use karo. Aur sunlo — return hote hi function turant khatam ho jata hai!

// return = value wapas bhejo function add(a, b) { let sum = a + b; return sum; // sum bahar bheja + function KHATAM } let result = add(3, 5); // result = 8 — return ki hui value aa gayi! console.log(result); // 8 console.log(add(10, 20) * 2); // seedha expression mein bhi → 60 // return = EXIT DOOR — iske baad kuch nahi chalta! function test() { return "bas!"; console.log("main kabhi nahi chalunga 😢"); // UNREACHABLE! }
BOMB ALERT: return Bhool Gaye = undefined!

Function ne kaam kiya par return nahi likha? JS khud hi bol dega return undefined;!
function add(a, b) { let sum = a + b; } — ab add(2, 3) → undefined, 5 NAHI! Machine ne juice banaya, par delivery hi nahi ki 📦❌. Aur ek trap: return ke baad wali lines kabhi nahi chalti — "unreachable code". Linter warning bhi deta hai — return hamesha aakhri kaam hona chahiye!

Golden Rule: Function return Kare, Bahar Log Karo

Best practice: function sirf return kare (pure kaam kare), aur jahan dikhana hai wahan console.log(fn(...)) karo. Kyu? Return karne se function reusable banta hai — 10 jagah use kar sakte ho; console.log andar kar diya toh result sirf screen pe gaya, haath mein nahi aaya!

Tool #4

Arrow Functions — Modern Shortcut ⚡

ES6 (JavaScript ka naya version) ne functions ka shortcut style diya — => (arrow). Chhota code, clean look,Callbacks ka best friend. 3 avatars hai — dekho same kaam 3 tareeke se:

// Avatar 1: Normal function function square(n) { return n * n; } // Avatar 2: Arrow — full body const square2 = (n) => { return n * n; }; // Avatar 3: Arrow — one-liner (return CHHUPA hua hai!) const square3 = n => n * n; console.log(square3(6)); // 36 — teeno SAME kaam karte hai! // Multi-param + no-param: const add = (a, b) => a + b; const hello = () => "Hi! 👋";
BOMB ALERT: {} Lagao Toh return LIKHNA PADEGA!

One-liner arrow mein return chhupa hota hai — n => n * n automatically return karta hai. Par curly braces lagate hi magic khatam:
const bad = n => { n * n; } → bad(5) = undefined! 😱 Kyunki {} lagate hi JS samajha "ye body hai, isme return likha hi nahi gaya". Fix: braces hatao, YA khud return likho: n => { return n * n; }. Ye trap interviews mein bhi milta hai!

Kab Arrow, Kab Normal?

Arrow: chhote one-liner helpers, callbacks (setTimeout(() => ...)), ek line ke kaam. Normal: bade functions, object ke methods, jab this chahiye. Rule of thumb: 1-2 line ka kaam = arrow; bada logic = normal. this wali baat abhi headake wali lagti hai — DOM chapter (Ch8) mein iska asli khel dikhega, tab saaf ho jayega!

Tool #5

Function Expression & Hoisting — Value Ka Khel 🎁

JS mein function sirf code nahi — VALUE hai! Variable mein store kar sakte ho, doosre function ko bhej sakte ho, array mein bhi rakh sakte ho. Isi liye JS ko kehte hai — functions are "first-class citizens" 🏆. Aur is value wali soch se ek naya concept banta hai: hoisting!

// Function EXPRESSION — function ko variable mein daala const dance = function() { console.log("💃 Naach raha hu!"); }; dance(); // variable ke naam se call hota hai // HOISTING MAGIC: Declaration — PEHLE call, BAAD mein define? sayHi(); // ✅ "Hi!" — chal gaya!! function sayHi() { console.log("Hi!"); } // Par expression mein yahi jadu NAHI hai: dance2(); // ❌ TypeError! const dance2 = function() { console.log("Hi2"); };
BOMB ALERT: Sirf DECLARATION Uchhalti Hai!

JS page load hote hi saari function declarations ko upar utha leta hai (isko hoisting kehte hai) — isliye define hone se pehle bhi call chal jaati hai. Par expression sirf ek variable hai — variable toh line chalne ke baad hi banta hai, isliye pehle call = TypeError: dance2 is not a function!
Interview mein seedha sawal: "declaration aur expression — kaunsa hoist hota hai?" — jawab pakka yaad rakho: sirf declaration!

Function = Value = Superpower

Kyunki function value hai, isliye: const ops = [add, sub, mul]; (functions ki array!), let op = add; (copy), functions ko arguments mein dena (callback — agla tool!) — sab possible hai. JavaScript apps ka poora architecture isi EK fact pe khada hai. Ch1 mein socha tha "variable mein sirf numbers hote hai"? Ab function tak variable mein aa gaya! 😎

Tool #6

Callbacks & IIFE — Function Ko Kaam Pe Bhejo 🤝

Function value hai, toh argument mein bhi de sakte hai! Jo function doosre function ko diya jaye use callback kehte hai — "bhai ye mera number, kaam hone pe CALL kar lena!" Aur IIFE = aisa function jo define hote hi khud hi chal jata hai — bina kisi ke bulaye!

// CALLBACK: function ko argument mein doosre function ko function baadMein(kaam) { // kaam = ek FUNCTION mila! console.log("Taiyari ho rahi..."); kaam(); // ab call kiya — yahi callback hai! } baadMein(function() { console.log("🎉 Party!"); }); // Taiyari ho rahi... / 🎉 Party! // REAL WORLD — setTimeout: 2 sec baad chalao setTimeout(() => { console.log("2 second ho gaye! ⏰"); }, 2000); // IIFE — define + call ek saath (aakhri () hi call hai!) (function() { console.log("Main bana AUR turant chal gaya! 🚀"); })();
BOMB ALERT: Callback Ko ( ) Mat Lagao!

Callback dena hai toh sirf naam do, call mat karo:
setTimeout(greet(), 2000) ❌ — greet ABHI chal gaya (return value chale gayi, jo ki function nahi hai)!
setTimeout(greet, 2000) ✅ — greet ka reference gaya, 2 sec baad setTimeout use call karega. Yaad hai Tool #1 ka wish; wala farak? Wahi concept ulta direction mein — dena hai toh naam, chalana hai toh ()!

Yeh Sab Kaha Use Hota Hai?

Callback: button click (btn.addEventListener("click", function() {...})), timers, API se data aane pe kya karna hai — poora web development callbacks pe khada hai! Ch8 (DOM) mein yahi roz use hoga.
IIFE: ek baar chalne wala setup code — apna private dabba banata hai taaki uske variables bahar leak na ho. let/const (Ch1) se pehle ke zamane mein yahi private scope ka tareeka tha!

🟡 Medium Task 3: maxOf3() — Teen Mein Se Bada

Function maxOf3(a, b, c) likho jo teen numbers mein se bada return kare. Chapter 3 ki if/else yaha andar kaam karegi! Test: maxOf3(10, 25, 7) → 25.

Idea: Pehle a >= b check karo — true toh a/c compare karo; warna b/c compare karo. Ya pehle big = a maan lo, phir b aur c se if (x > big) big = x;
function maxOf3(a, b, c) {
  let big = a;              // maan lo a bada hai
  if (b > big) big = b;     // b ne haraya?
  if (c > big) big = c;     // c ne haraya?
  return big;
}

console.log(maxOf3(10, 25, 7));  // 25

// Tournament style — maxOf do baar:
function maxOf3v2(a, b, c) {
  return Math.max(a, b, c);  // built-in cheat 😄
}

🔴 Hard Task 5: getGrade() — Early Return Pattern

Function getGrade(marks) likho: 90+ → "A+", 75+ → "A", 60+ → "B", warna "C". Trick: har check ke saath turant return karo — ye early return pattern hai, pro coders ka favourite!

Idea: if (marks >= 90) return "A+"; — return hote hi function khatam, isliye agla check sirf tab hoga jab pehla fail hua. Ladder jaisa — pehli seedhi pe mil gaya toh neeche nahi dekhna!
function getGrade(marks) {
  if (marks >= 90) return "A+";
  if (marks >= 75) return "A";
  if (marks >= 60) return "B";
  return "C";   // baki sab
}

console.log(getGrade(95));  // A+
console.log(getGrade(80));  // A
console.log(getGrade(40));  // C

// else-if ladder se SHORT aur clean!
🔴 Hard Task 6: factorial() — Ch4 Ko Function Mein Convert!

Chapter 4 mein factorial loop se nikala tha — ab wahi loop function ke andar daalo: factorial(n) return kare n! (5! = 120). Bonus: factorial(0) → 1 bhi sahi aana chahiye!

Idea: Accumulator fact = 1 (0 se nahi!) loop se pehle banao. Loop 1 se n tak guna karta jaye, end mein return fact. n = 0 pe loop chalega hi nahi — fact = 1 hi return — automatic sahi!
function factorial(n) {
  let fact = 1;             // 1 se shuru — 0 se NAHI!
  for (let i = 1; i <= n; i++) {
    fact = fact * i;
  }
  return fact;
}

console.log(factorial(5));  // 120
console.log(factorial(0));  // 1 ✅ (loop nahi chala)
console.log(factorial(1));  // 1

Mini Calculator

Do number + operator do, jawab lo — switch (Ch3) function ke andar! Calculator app ka dil yahi hai.

switchparams
function calc(a, b, op) {
  switch (op) {
    case "+": return a + b;
    case "-": return a - b;
    case "*": return a * b;
    case "/": return a / b;
    default: return "Galat operator!";
  }
}

console.log(calc(12, 4, "*"));  // 48
console.log(calc(10, 0, "/"));  // Infinity 😱

Challenges: 1) Divide by zero handle karo (0 pe "Infinity nahi!" return). 2) % operator add karo. 3) Ek call mein poora expression: calc("12", "*", "4") strings se bhi chale!

Password Generator

Length do, strong password lo — loop se characters uthao, random se mix karo. Hacker-proof (almost!) 😄

loopstring build
function makePassword(len) {
  let chars = "abcdefghjkmnpqrstuvwxyz"
            + "ABCDEFGHJKMNPQRSTUVWXYZ"
            + "23456789@#$%&!";
  let pass = "";
  for (let i = 0; i < len; i++) {
    let idx = Math.floor(Math.random() * chars.length);
    pass += chars[idx];
  }
  return pass;
}

console.log(makePassword(10));

Challenges: 1) Pakka ek number aur ek symbol ho — pehla char fix karo! 2) strengthCheck(pass) function: length + types check karke "Weak/Medium/Strong" return karo. 3) 5 passwords ka array ek hi call mein — makePasswords(5, 12)!

16 Interview Questions — Functions Edition 💼

Cheat Sheet

Ek Nazar Mein Sab Kuch 📋

Interview/exam se ek ghanta pehle — bas yeh 4 boxes revise kar lo!

Syntax Reference

declarefunction naam(a, b) { ... }
callnaam(1, 2); ← () ZAROORI!
defaultfunction f(a = 10) { ... }
returnreturn value; (exit bhi!)
arrow 1const f = x => x * 2
arrow 2const f = (a, b) => { return ... }
expressionconst f = function() { ... }
IIFE(function() { ... })();
callbacksetTimeout(fn, 1000)

Kab Kya Use Kare?

  • declaration — general use, hoisting chahiye toh
  • arrow — chhote helpers + callbacks
  • expression — function ko value ki tarah store/dena
  • callback — click, timer, data events
  • IIFE — one-time setup, private scope
  • Naam verb se — greetUser, calcFee, isValid
  • Ek machine = ek kaam — chhoti rakho!

Common Mistakes

  • Call mein () bhool gaye → silent no-op, error bhi nahi!
  • return bhool gaye → hamesha undefined milega
  • return ke baad ki lines — kabhi nahi chalti (unreachable)
  • Expression define se pehle call → TypeError (hoisting sirf declaration pe!)
  • Arrow + { } + return nahi likha → undefined
  • console.log ≠ return — dikhana vs dena!
  • Kam arguments → undefined → NaN cascade
  • Callback dena ho toh fn() nahi, sirf fn!

Interview Facts

  • Functions are first-class citizens — value jaise use hote hai
  • Sirf declarations hoist hoti hai, expression nahi
  • Arrow ka apna this / arguments nahi hota
  • return = instant exit door — wahi se function khatam
  • DRY — Don't Repeat Yourself — functions ka motive!
  • Callbacks = DOM/events ka base (Ch8 mein sab use hoga)
  • Recursion ko base case chahiye — warna infinite!
  • Default parameters = ES6 feature — undefined se bachav
